CCNA 200-301 MASTER STUDY PLAN
French Toast Networks

OVERVIEW
--------
This program uses 58 short story-mode episodes across seven seasons.

There is no fixed calendar. Progress is session-based.

Recommended pace:
- Flexible
- Usually 3–5 sessions per week
- Pause for review whenever the knowledge register shows weak retention
- Labs are optional and separate

EXAM DOMAIN WEIGHTING
---------------------
1. Network Fundamentals — 20%
2. Network Access — 20%
3. IP Connectivity — 25%
4. IP Services — 10%
5. Security Fundamentals — 15%
6. Automation and Programmability — 10%

LEARNING MODEL
--------------
Every session should move through this sequence:

1. Story setup or ticket
2. Recall from earlier knowledge
3. One Socratic question
4. Learner prediction
5. Evidence or device behaviour
6. Brief teaching
7. Exam lens
8. Applied closing check
9. Continuity outputs

DEPTH RULE
----------
The exam verb controls depth.

Describe:
- Explain purpose and behaviour
- Recognise examples
- Compare with nearby concepts
- Do not force unnecessary configuration

Configure and verify:
- Understand concept
- Know required commands
- Interpret output
- Predict device behaviour
- Troubleshoot common failure cases

Interpret:
- Read tables, CLI output, topology diagrams, and GUI settings
- Distinguish relevant from irrelevant evidence

SEASON STRUCTURE
----------------
Season 1 — Opening the Toast Rack
Network foundations, Ethernet, IOS, switching basics

Season 2 — Addresses on the Menu
IPv4, subnetting, IPv6, ARP, addressing logic

Season 3 — Le School de Croissant
VLANs, trunks, STP, EtherChannel, inter-VLAN routing

Season 4 — The Second Campus
Routing tables, static routes, OSPF, FHRP concepts

Season 5 — Managed Services
DHCP, DNS, NAT, NTP, SNMP, syslog, QoS, SSH, wireless

Season 6 — Secure the Bakery
ACLs, AAA, L2 security, WLAN security, VPN concepts

Season 7 — The Automated Kitchen
Controllers, SDN, APIs, JSON, Ansible, Terraform, AI/ML

ASSESSMENT MODEL
----------------
No large formal diagnostic before Episode 1.

Instead:
- One compact diagnostic at the start of each season
- One application check at the end of each episode
- One season checkpoint
- One optional integrated lab per season
- Final readiness assessment across all six domains

SUBNETTING MODEL
----------------
Use both:
- Dedicated subnetting episodes
- Short recurring subnetting drills in later sessions

Do not overload the learner with long calculation blocks.

OPTIONAL LAB MODEL
------------------
Teaching episodes do not require labs.

Labs should be:
- Separate
- Clearly numbered
- Optional
- Packet Tracer compatible by default
- Adaptable to CML, EVE-NG, GNS3, or physical equipment

CONTINUITY OUTPUTS
------------------
After each episode:
- Session summary
- Knowledge register
- Master mind map update

Do not automatically create:
- Long guides
- Songs
- HTML artefacts
- Large visual pages
- Podcasts

Create those only when specifically requested.
