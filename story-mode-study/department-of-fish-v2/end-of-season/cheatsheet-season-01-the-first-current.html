CORE MENTAL MODELS

The Five Ideas That Carry Everything

  • Alive ≠ Good. Alive = probe returned. Good = within SLA thresholds. Independent.
  • First packet chooses, then it's cached. Rule lookup happens once at session birth; forwarding is reused after that.
  • Only two re-evaluation triggers: manual clear, or genuine FIB/route change. Never an SLA verdict alone.
  • Disappearance ≠ appearance. A route vanishing triggers re-evaluation; a route returning does not.
  • Filter, then tiebreak. Best Quality / Lowest Cost both: SLA compliance filters first, tiebreaker decides among survivors.
KEY DECISION ORDERS

Lookup Sequence

  1. Explicit SD-WAN rule table (top-down, first match)
  2. ↓ no match →
  3. Implicit rule (load-balance-mode + FIB, Alive+route required)
Trap: "rule fails to match" ≠ "traffic dropped." It falls through to the next rule / implicit rule.
CRITICAL DEFAULTS & BEHAVIOURS

Don't Forget

  • sla_map = LSB-first, one bit per SLA target within one member (not per member).
  • Manual strategy = totally SLA-blind; first Alive member in preference order.
  • Implicit-rule eligibility = Alive AND valid FIB route — both required.
  • weight-based = static ratio; usage-based = live measured throughput.
  • Best Quality's link-cost-factor = exactly ONE metric, never a blend.
  • Local breakout ≠ lost visibility — inspection source moves, FAZ still gets the logs.

TOP EXAM TRAPS THIS SEASON

Most Important Facts to Remember

1. sla_map is per-target-within-one-member, not per-member.
2. SLA verdict alone never re-evaluates an existing session.
3. Route returning ≠ trigger; only disappearing is.
4. Two-stage decisions (filter → tiebreak) get collapsed to one stage under pressure — check both stages before answering.
5. Local breakout keeps visibility via FortiAnalyzer — it doesn't lose it.
