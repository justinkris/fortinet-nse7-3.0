01

Core mental models

  • A template is an author, not a place. One-to-many at authoring time; one-per-device at storage time. Two authors, one page — the template wins.
  • Blast radius is authorship, not device. An install overwrites the config blocks an assigned template writes, in full. Absence inside an authored block is deletion.
  • Hand-edit safety is a property of the current assignment set — and that set can change without anyone touching the device.
  • A blueprint is a one-shot recipe. No ongoing link. Fixing it never repairs a deployed device.
  • The FortiGate is a parser, not a compiler. Install scripts are consumed line by line; a reference is validated against what exists at that instant.
  • An overlay is a hub-transport pair, and exists only where both ends carry the transport.
  • The asymmetry comes from who knows whose address. Hub static and knowable → spoke is the static-type initiator; hub is the dynamic dial-up server.
  • Three lookups per encapsulated flow: inner destination, recursive next hop, outer header.
  • The routing table does not move when a transport fails. Only the resolved member set shrinks.
  • BGP decides which hubs; SD-WAN decides which tunnel. Neither can do the other's job.
  • Failover happens at the layer that has candidates.
🧠
MENTAL NOTE
If you remember one sentence: anything the template writes is borrowed, not owned.

06

Exam traps

Empty Installation Target = all devices, not none.
A second hub does not join existing overlays. Dual hub, two transports = four tunnel subnets.
hubs × transports fails under asymmetry. An overlay exists only where both ends carry the transport — count per transport.
The BGP-on-loopback saving is in sessions and routes, not tunnels. Tunnel count is set by the IPsec topology.
Assignment writes the device DB. The install gap is device DB → firewall, never template → device DB.
Overwrite scope is authorship of blocks, not modification of settings.
A route present but not forwarding is unresolvable or beaten on administrative distance. SD-WAN cannot stop a route entering the FIB. — Needs Reinforcement
Without ibgp-multipath, a fully tunnelled second hub is not a failover candidate, and recovery waits on the hold timer. — Needs Reinforcement
An unresolvable route leaks to the default route. It does not drop cleanly. — Needs Reinforcement
network-id prevents cross-overlay traffic at runtime; it is not an addressing control.
Weights do nothing unless the zone is in volume load-balance-mode. Installs clean, reports success, changes nothing.
Removing a variable reference does not delete mappings. Deleting an override does destroy data.
Existence prerequisites vs planning inputs are two different questions. Existence: hubs managed with links configured; branches in a device group; one ADOM; one overlay template per FortiGate. Planning: topology type, overlay space, loopback space, AS number.
🧠
MENTAL NOTE
Most traps in this material are inversions: the right fact pointed the wrong way. Check direction before you check content.

The five facts most worth remembering

  1. Anything the template writes is borrowed, not owned — and absence inside an authored block is deletion.
  2. Hand-edit safety is a property of the current assignment set, which can change without touching the device.
  3. Empty Installation Target means every device.
  4. An overlay is a hub-transport pair; both ends must carry the transport.
  5. BGP decides which hubs; SD-WAN decides which tunnel — and SD-WAN can only choose what the FIB has resolved.
