SUPP-01 · Mind Map · Layer / Scope / Value / Install

The Four Pillars

Read each column top to bottom: the question, what decides it, the mechanisms, the rule, the trap.

Every column answers one question. Every row answers it the same way.

Question → decided by → mechanisms → the one rule → the one trap. Scan down for depth, scan across to compare.

THE MAP

Four questions, four columns

Before you touch a template Ask all four · in this order
1
LAYER
Which layer am I writing into?
DECIDED BY
The content. Box config or traffic decisions?
TWO ANSWERS
Device layerdevice DB · one per FortiGate
all provisioning templates Policy layerpackages + one shared
object DB per ADOM
THE RULE
Layer determines the install:
Device → Install Device Settings
Policy → Install Policy Package
THE TRAP
Device settings install will never deliver a policy or object change. Wrong layer, wrong install.
2
SCOPE
Who is this going to reach?
DECIDED BY
Two nested filters: coarse then fine.
MECHANISMS
Assignmentdevice or group
whole template · all-or-nothing Installation targetone setting · structured only
empty = everyone Jinja {% if %}conditional blocks
CLI templates only
THE RULE
Each template type has exactly one way to vary structure. Structured → targets. CLI → Jinja.
THE TRAP
There is no Jinja in an SD-WAN template, and no installation target in a CLI template. Don't reach for the tool the type doesn't have.
3
VALUE
Where does each value come from?
DECIDED BY
Metadata variables — one name, many values. $(x) = {{x}}, same store.
RESOLUTION ORDER
1 · Device overrideper-device mapping table 2 · Template defaultif no override 3 · BLOCKthat device only
THE RULE
Resolution happens at write time. Device DB and FortiGate only ever hold the literal.
THE TRAP ⚠ REINFORCE
Delete the override → default fallback.
Delete the reference → no lookup at all; the value survives, inert, and resurrects silently.
4
INSTALL
What will the box actually receive?
DECIDED BY
Install Preview — per device, resolved, assembled in order. The one evidence artefact.
THREE EVENTS
Assignlink only · status Modified
nothing written Installrenders into device DB
pushes to FortiGate Unassignlink removed
device DB keeps content
THE RULE
Failure is per device, never fleet-wide — unresolved variable, missing hardware, or invalid CLI all block only the affected box.
THE TRAP
Assign is not install. Modified status means "staged copy differs" — nothing has moved. Check Preview for the worst device, not the best.
