SESSION 04 · BITE · INDICATORS AND FABRIC FEEDS

The Fact and the Delivery

A fact nobody receives enforces nothing. Fifty points for getting it there — fifty for making it usable.

The judges split these two objects on purpose.

Boardroom, World 2 — Indicators 50 pts, Fabric Feeds 50 pts. You lose the second fifty by proving the feed arrived and calling the job done.

💭 THINK FIRST · TWO OBJECTS

The tempting answer is scale — nobody wants to write a policy per name. That answer is true and still wrong, because it describes a side effect rather than a job. Strip the scale argument away and the real question surfaces.

  • If a feed carried exactly one entry, would it still earn its fifty points?
  • What does the feed do to a fact that the fact cannot do for itself?
Q1 — MODEL ANSWER
Yes. The value is not list length. A single-entry feed still crosses the gap and still lands the fact in a referenceable shape — both jobs, done once.
Q2 — MODEL ANSWER
Two things at once: it transports the fact to the enforcement point, and it converts the fact into an object a policy or profile can point at. Bundling is the by-product.
SECTION 01

Two Objects, One Gap

An indicator is a fact — an IP, URL, domain, or MAC address known to matter. It lives on FortiAnalyzer, under Incidents & Alerts > Indicators. It is true whether or not anybody acts on it, and it enforces nothing.

A fabric feed is the delivery of usable facts. The FortiGate dynamically imports a plain-text list over HTTP/HTTPS and holds it as an external resource — an object that policies and profiles can reference. Feeds are synchronised periodically. STIX/TAXII is also supported.

The gap: the fact starts on one box and has to be actionable on another. Closing that gap is the feed's entire job. Scale is what you notice second.
Analogy

A name on a napkin is not a doorman.

  • Doc writes a name down — that is the indicator. Accurate, useful, inert.
  • Somebody has to walk it to the door and pin it where the doorman reads — that is the feed.
  • The doorman still has to be told to check the list — that is the reference.
🧠
MENTAL NOTE
Indicator = fact; feed = delivery of usable facts.
SECTION 02

Five Stages, All Silent

Known→ Delivered→ Present→ Referenced→ Matched
  • Known — the fact exists at the source. Somebody wrote it down.
  • Delivered — the feed carried it across the gap. Fails on timing, reachability, or content.
  • Present — it is sitting in an object on the FortiGate. Existing. Doing nothing.
  • Referenced — a policy or profile points at that object. Armed, but only inside that one rule.
  • Matched — traffic hits that rule and the comparison actually succeeds.

Not one of these stages raises an error when it breaks. Traffic simply keeps going. That is why you cannot troubleshoot this by feel — you walk the chain and you kill stages with evidence.

Order discipline: once a stage is cleared by evidence, it stays dead. Going back to re-inspect a policy the log has already exonerated finds nothing and costs you the round.
🧠
MENTAL NOTE
Known ≠ received ≠ usable. Present ≠ referenced. Referenced ≠ matched.
SECTION 03

Configuring the Indicator

FortiAnalyzer 8.0.0 Administration Guide — Incidents & Alerts, pp. 359–365

Create

Incidents & Alerts > Indicators > Create New → select the Indicator type → enter the Indicator Value (IP, URL, domain, or MAC) → Create.

Faster from evidence: in Log View, right-click an ip, url, domain, or mac-address and choose Create indicator and block — adds it and blocks it in one action. Indicators also arrive automatically, attached to incidents from FortiGuard, FortiMail, or FortiSandbox, and attached from alerts where the alert handler creates them (up to five per handler, each with Log Field / Indicator Type / Count).

Enrich

Select the indicator → Enrich → review → Save Enrichment. Runs on the predefined, read-only, enabled-by-default Indicator Enrichment playbook. FortiGuard enrichment is built in; VirusTotal needs an API key set under Incidents & Alerts > Automation > Active Connectors. Returns FortiGuard CTS (confidence, IOC tags, AV and web filter categories) plus VirusTotal Risk Summary, Detection, and Details.

Two quiet ones: nothing is processed until you click Save Enrichment — opening the pane is not enriching. And private IP addresses are not valid IP indicators, so Enrich greys out.

Block

Available from Indicators, from Incidents, and from Incident Analysis. Requires a connector — without one, Block is greyed out.

FortiMQ ConnectorFortiManager Connector
ScopeADOM-specific — only FortiGates in the same Fabric/FortiGate ADOMGlobal

Status flow: Blocked (Pending) → the backend block_indicator playbook runs every five minutes → Blocked. The Indicators pane shows a Block Status column and pie chart with TBD / Blocked / Unblocked.

FortiMQ prerequisites — all three: logging enabled from the FortiGates to FortiAnalyzer; FortiAnalyzer and FortiGate registered under the same FortiCare account; and Cloud-based Fabric Feed synchronization enabled and configured on the FortiGate.
Direction — say it out loud: FortiAnalyzer sends to FortiMQ and stops. The FortiGate retrieves the indicators from FortiMQ and updates them into its external feeds. FortiAnalyzer never writes to the Gate.
Requires official Fortinet source verification The FortiGate-side screen and CLI for Cloud-based Fabric Feed synchronization. The FortiAnalyzer guide names it as a prerequisite and points to the FortiOS 8.0 New Features Guide, which is not in this pack. Know the name and know it is the Gate's half of the FortiMQ relationship — do not guess the path.
🧠
MENTAL NOTE
Blocked (Pending) is not blocked. The playbook runs on a five-minute cycle, and FortiMQ only reaches Gates inside its own ADOM.
SECTION 04

Configuring the Feed

FortiOS 8.0.0 Administration Guide — Fortinet Security Fabric, External feeds, pp. 4943–4969

Security Fabric > External Connectors → Create New → External Feeds → pick the type → set Name, Update method: External Feed, and URL of external resource. With VDOMs enabled, SDN and External Feeds connectors sit in global settings.

FortiOS CLI
config system external-resource
    edit "AWS_IP_Blocklist"
        set type address
        set resource "https://blocklist-example.com/ip-blocklist/ip.txt"
        set server-identity-check {none | basic | full}
    next
end

server-identity-check defaults to none — certificate validation is off unless you set basic or full. For HTTPS servers demanding mutual TLS, add set client-cert-auth enable and set client-cert <name>; those auth events land in Log & Report > System Events > Logs.

The five types — and what consumes each

This table is the stage-five problem. A domain-shaped fact referenced by something that cannot see domains never matches. The rule runs, the reference is valid, the traffic passes, nothing errors.

File format and limits

  • Plain text, one entry per line; # starts a comment. Update period: 1 minute, hourly, daily, weekly, or monthly (43200 min / 30 days). No duplicate validation.
  • Category (URL): scheme optional and truncated; wildcards at start or end; IDN/UTF supported; IP allowed but not private IPs; IPv6 in [ ].
  • Address: single IP, subnet, or range, IPv4 or IPv6 — IPv6 needs no brackets.
  • Domain: simple wildcards such as *.test.com; IDN supported.
  • MAC: single, OUI, or range; hex digits colon-separated only.
  • Malware: strict — <hex hash> [description], MD5/SHA1/SHA256. A missing space or an underscore instead makes the entry invalid. Don't mix hash types in one list.
  • Limits: global entry cap; file size 128 / 64 / 32 MB by model range. Over the cap, the most recently added entries truncate unless reordered with move "entry2" before "entry1". Check yours with print tablesize. Category and domain types share category numbers 192–221 — 30 slots total.
🧠
MENTAL NOTE
Name the consuming profile before you build the feed. If you cannot name it, you do not own that type.
SECTION 05

Proving It — Evidence per Stage

StageWhere you lookWhat it proves
KnownFAZ Incidents & Alerts > Indicators — exists, Block StatusThe fact was established and dispatched
DeliveredFGT Security Fabric > External Connectors → Edit → Last UpdateThe Gate retrieved, and when
PresentSame connector → View EntriesThe specific fact landed in the object
ReferencedThe consuming profile or policy from Section 04The fact is armed — in one rule only
MatchedLogs — see belowThe comparison actually happened

The log line is the only artefact that proves stage five. A web filter or SSL event carries the feed name as cat=192 catdesc="Custom-Remote-FGD"; a DNS filter event as cat=194 catdesc="Domain_monitor_list". A remote-category match overrides the URL's original FortiGuard rating — cross-check the original with FortiGuard Web Filter Lookup before you conclude anything about categorisation.

FortiOS CLI — verification
diagnose sys external-resource stats                 # per-VDOM feed and entry counts
diagnose sys external-mac-resource list <FEED_NAME>  # MAC ranges actually loaded
diagnose debug flow trace start 10                   # local-in drops: iprope_in_check() ... drop
Cheapest evidence first. When traffic passes unexpectedly, the first question is not why didn't it match — it is which rule matched at all. A different policy means wrong path and the feed is innocent. The intended policy means the rule ran and you are at stage five.
🧠
MENTAL NOTE
Last Update proves delivery. View Entries proves presence. Only a log line carrying your feed name in catdesc proves enforcement.
SECTION 06

The Trap List

  1. A stale feed still enforces. Lose connectivity to the external server and the feed keeps working — Connection Status errors, entries survive reboot, but nothing new is added until the connection returns. Configured, working, and quietly out of date.
  2. Allow does not allow. On a remote category, Allow means no filter applied and will not override the FortiGuard Category Based Filter action. Only Monitor and Block override. Avoid Allow on remote categories.
  3. Wrong consumer for the type. Domain feed into a DNS filter; URL list into a web filter; hash into an AV profile. Mismatch and you get a silent pass.
  4. server-identity-check defaults to none.
  5. Truncation takes the newest entries. Over the cap, the most recently added drop — which is exactly the indicator you just created.
  6. 192–221 is shared. Category and domain feeds compete for the same 30 slots.
  7. FortiMQ is ADOM-scoped; FortiManager is global. FortiMQ wins when both are active, so a Gate in the wrong ADOM silently never receives the block.
  8. Malware hash feeds do not work in AV quick scan mode.
Bench work before the next round: build one feed of each type and name its consumer before opening it; walk one feed end to end from Last Update to a catdesc= log line; then point a feed at a dead host and confirm it still enforces the old entries. That last one is trap 1, and it will be on the board.
🧠
MENTAL NOTE
Every trap on this list is silent. Nothing on the screen looks broken — which is why the evidence chain, not the screen, is what you trust.
