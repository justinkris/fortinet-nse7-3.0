# NSE7 EF 7.6 — Project Instructions (3.0)

Simple sort + build pipeline. `sorting-hat/` is the inbox; `python3 build.py` regenerates every session's `index.html` and re-runs `build_flashcards.py`.

## Directory layout

├── build_prompts.py              # invoked by build.py; writes images/prompts.txt
├── build_image_swap.py           # invoked by build.py; injects placeholder-hide CSS/JS
├── knowledge-register.txt        # shared, overwritten each sort
├── sorting-hat/                  # inbox
├── sessions/
│   └── session-NN-<slug>/

One file per subfolder, per session. The subfolders are plural to mirror the nse7-2.0 convention even though only one item lives in each.

## Sort workflow

Trigger phrases: **"sort"**, **"sort please"**, **"process the sorting hat"**.

Steps:

1. **List** every file in `sorting-hat/`.
2. **If any `.zip` is present**, extract it in place (`unzip -o files.zip -d .` then `rm files.zip`) and continue with the contents.
3. **For each session number `NN` found**, read `session-NN-complete-guide.html`'s `<title>` tag. Strip the `Session NN Complete — ` prefix and kebab-case the remainder to get the slug. Destination folder is `sessions/session-NN-<slug>/`. If the complete-guide file is missing for a session but other files reference the same `NN`, halt and ask.
4. **Classify** each file against the table below. Anything that doesn't match → halt and ask. Never invent a destination.

| Filename | Destination |
|---|---|
| `session-NN-complete-guide.html` | `sessions/session-NN-<slug>/guides/complete-guide.html` |
| `session-NN-bite.html` | `sessions/session-NN-<slug>/bites/bite.html` |
| `session-NN-nibble.html` | `sessions/session-NN-<slug>/nibbles/nibble.html` |
| `session-NN-troubleshooting.html` | `sessions/session-NN-<slug>/troubleshooting/troubleshooting.html` |
| `session-NN-visual.html` | `sessions/session-NN-<slug>/visual/visual.html` |
| `session-NN-summary.txt` | `sessions/session-NN-<slug>/summary.txt` |
| `session-NN-revision-pack.txt` | `sessions/session-NN-<slug>/revision-pack.txt` |
| `end-of-season-N-review.html` | `end-of-season/season-N-review.html` |
| `knowledge-register.txt` | project root (overwrites silently) |
| `knowledge-register-sessionN.txt` | `sessions/session-NN-<slug>/knowledge-register.html` (rendered — see below) |

5. **Collision check** — if the destination folder already exists for that session, existing `.html`/`.txt` files are overwritten silently but print a heads-up per file (`replacing existing guides/complete-guide.html for session NN`).
6. **Move** with `mv` — never `cp`. `sorting-hat/` must be empty after a successful sort.
7. **Always create `visual/images/`** in every session touched, even if no image files are being placed. This is the drop zone for generated PNGs referenced by `visual.html`.
8. **Extract prompts from `visual.html`** and write them to `visual/images/prompts.txt` (overwrite each sort). Each block in `visual.html` carries a filename element and a prompt element under one of these markup variants:

   | Filename class | Prompt class | Caption class (optional) |
   |---|---|---|
   | `ip-filename` (div) | `prompt-content` (hidden div) | `ip-caption` |
   | `ip-filename` (div) | `ip-prompt` (div) | — |
   | `ph-filename` (div) | `prompt-content` (div) | — |
   | `si-filename` (span) | `prompt-content` (hidden div) | `img-caption` |

   Strip any leading `images/` path from the filename (they're already in `images/`). Emit one block per prompt in this shape:

   ```
   <Session NN Visual — page title>
   ============================================================

   Save as: <filename>.png

   Title: <caption if any>

   Prompt:
   <full prompt text>

   ============================================================
   ```

9. **Rebuild** with `python3 build.py`. The build walks `sessions/` and regenerates each session's `index.html`, then invokes `build_flashcards.py` to rebuild `flashcards/` from every `revision-pack.txt`'s `FLASHCARDS` section (Q:/A: pairs).
10. **Report** to the user: one row per file (source → destination). Note any overwrites.

## Flashcards

`flashcards/` is fully generated — never hand-edit files under it. `build_flashcards.py` walks every `sessions/session-NN-<slug>/revision-pack.txt`, finds the `FLASHCARDS` section (any of the header variants: `FLASHCARDS`, `3. FLASHCARDS`, `FLASHCARDS (Q -> A)`), extracts Q:/A: pairs, and writes:

- `flashcards/index.html` — two-button hub linking to Sessions and Chapters.
- `flashcards/sessions/index.html` — one button per session with card counts; empty decks render greyed-out.
- `flashcards/sessions/session-NN-<slug>.html` — click-to-flip deck (space/enter flips, ← / → navigates, Shuffle button randomises order).
- `flashcards/chapters/index.html` — placeholder until chapter-based decks are wired up.

The build runs automatically as the last step of `python3 build.py`. Sessions with no `FLASHCARDS` section appear in the hub as empty tiles.

## Prompts extraction

`build_prompts.py` runs after flashcards. It walks `justins-pages/*/*.html` and every `sessions/session-NN-<slug>/visual/visual.html`, extracts image prompts from any of these markup variants, and writes them to the sibling `images/prompts.txt` (overwriting whatever was there):

- `ip-filename` / `ph-filename` / `si-filename` + `prompt-content` (hidden div) — the standard visual pattern
- `ip-filename` + `ip-prompt`
- `imgph-title` + `imgph-prompt` (no filename → slugified from title) — newer session-visual variant

Pages with no embedded prompts are left alone (their `images/prompts.txt`, if any, is preserved). No need to hand-write `prompts.txt` for a visual page ever again — put the prompt in a `prompt-content` div and rebuild.

## Image-placeholder auto-swap

`build_image_swap.py` runs last. It injects an idempotent `<style>` + `<script>` block before `</body>` in every `justins-pages/*/*.html` and every `sessions/session-NN-<slug>/visual/visual.html`. The block is bracketed with `<!-- image-swap:vN -->` markers so re-runs replace (never duplicate) the payload.

Runtime behaviour: on page load, any wrapper matching `.image-placeholder`, `.imgph`, or `.ip-container` that contains an `<img>` which loaded successfully gets an `img-loaded` class; the CSS then strips the dashed border/padding/background and hides all non-image children of the wrapper (filename hint, title, caption, prompt body). If the PNG is missing, the placeholder stays intact.

To upgrade the payload, bump `MARKER_VERSION` in `build_image_swap.py` and rebuild — the old block will be swept out by the version-agnostic regex.

## End-of-season reviews

When a season closes, a review file lands in `sorting-hat/` as `end-of-season-N-review.html`. Sort it to `end-of-season/season-N-review.html`. The `end-of-season/` folder is at the project root and holds:

- `index.html` — hand-written button grid with one button per season (`Season 1`, `Season 2`, …). Add a new button when a new season lands; keep future seasons visible as `btn-empty` placeholders. The build script does **not** regenerate this file — edit it in place.
- `images/` — shared drop zone for any PNGs referenced by the season-review pages.
- `season-N-review.html` — one per season, moved from the sorting-hat.

Season-review pages are self-contained (their own inline CSS) and are not walked by `build.py`.

## Per-session knowledge-register snapshots

The shared `knowledge-register.txt` at the project root is the **current** cumulative register — overwritten every sort. In addition, each session gets its own **snapshot** as `sessions/session-NN-<slug>/knowledge-register.html`, so the state of the register at the close of that session is preserved even after later sorts overwrite the shared file.

**Filename pattern:** `knowledge-register-sessionN.txt` (no zero-pad on `N`) in the sorting-hat. During sort:

1. Match `N` to a session folder in `sessions/` (fail loudly if none exists).
2. Read the txt, HTML-escape its body, drop it into a cream-and-blue template as a `<pre>` block (preserves the fixed-width formatting, star ratings, and section separators of the register).
3. Write to `sessions/session-NN-<slug>/knowledge-register.html`. The subpage tile picks it up on the next build via the `knowledge-register` entry in `SUBPAGES`.
4. `mv` the txt out of `sorting-hat/` (delete after rendering — the shared cumulative register at the project root is the authoritative txt copy; per-session snapshots live only as HTML).

The tile chip color is muted-gold (`--gold` family) so it doesn't collide with any of the existing subpage chips.

## Hard rules

- Sort is a pure **move + rebuild**. Never edit file contents during the move.
- If a file fails to classify or the slug can't be extracted, leave it in `sorting-hat/` and halt. Do not delete.
- `sorting-hat/` is the only inbox — don't accept content pasted directly.
