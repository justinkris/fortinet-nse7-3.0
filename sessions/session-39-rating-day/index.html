Concepts Covered 11 concepts
  1. 01
    SECURITY RATING ARCHITECTURE
    root compiles a fabric-wide audit; each member FortiGate self-checks its own config against best-practice checks and reports results upward. Same distribute-work/centralise-verdict pattern as stitches (config authored on root, executed locally) and fabric logging (each member logs independently to FAZ).
  2. 02
    RATING RE-RUNS AUTOMATICALLY on a schedule (not just on click) — explains Riley's "why did this change with nobody touching it" ticket
    Can ALSO be triggered on-demand from the GUI — used to force a fresh score after Mon/Tue remediation, ahead of the scheduled cycle.
  3. 03
    SCORE ANATOMY
    weighted points per check (severity × device-importance) → letter grade. TWO context layers turn a floating number into board-usable information: (a) TREND — score over time, because the rating has been running since fabric go-live; (b) INDUSTRY PERCENTILE — compared to similar-sized organizations in the same sector. Both the full check set and percentile comparison require a FortiGuard Security Rating subscription; without it, checks and comparison degrade/vanish while local score/findings largely still compute — same asymmetric-degradation pattern as S23's FortiGuard web-filter outage. Diagnostic instinct reused correctly: `diagnose autoupdate versions` as the paperwork check.
  4. 04
    FINDINGS TRIAGE — THREE LENSES (beyond raw severity order)
    (a) EXPOSURE — who can reach it unprompted? internet / internal / post-compromise-only. (b) BLAST RADIUS — what does a successful exploit hand the attacker? (c) COST TO FIX — zero-disruption CLI change vs. requires a change window (e.g., firmware = reboot = plan around trading hours). Some findings offer a one-click remediation shortcut directly from the Rating page ("free wins").
  5. 05
    EXAMPLE FINDING SET WORKED
    critical = admin HTTPS enabled on WAN interface (precondition-free, internet-facing — categorically worse than anything requiring prior compromise); high = no trusted hosts on admin accounts (cheap, high-value insurance against credential/lateral-movement risk); medium = stale firmware on a branch box (schedule for change window, reboot risk); medium = "all/all" firewall policies (cannot be tightened safely from config alone — must audit actual traffic via FAZ logs, over a WIDE window to catch rare/periodic flows before assuming a service is unused); low = admin password policy not enforced (cheap, hour-one fix).
  6. 06
    CONFIG-BACKUP STITCH PROOF POINT
    Schedule-triggered backups land in Configuration > Revisions — the version-history page, also used for rollback. Hook: "Schedule trigger → Revisions page."
  7. 07
    SCHEDULE TRIGGER FREQUENCIES (corrected this session)
    Once, Hourly, Daily, Weekly, Monthly — NOT "Now." Governed by the ROOT FortiGate's system clock, because the stitch is authored on the root and pushed to leaves ("root's ink, root's clock"). This is a repeat-miss item (also missed cold in S38) — now flagged for an unprompted cold ambush in a future session rather than another warm-up.
  8. 08
    MANUAL QUARANTINE CLI (retained from S38, applied live)
    `diagnose endpoint fctems queue-complete-calls Q-<endpoint_ip_address>` — manually injects the same instruction EMS would send after an automated IoC detection. Not supported on FortiClient (Linux) — reconfirmed cold.
  9. 09
    SAML SSO ROLES (retest)
    root = sole IdP; downstream FortiGates, FortiAnalyzer, FortiManager = SPs. FortiAuthenticator is NOT part of this fabric SSO picture — it's a separate standalone IdP product; naming it as an SP was a planted distractor and was taken. "One fabric, one anchor, one voucher" derivation still solid; vendor-name-similarity traps remain a live risk pattern.

    Watching (FAZ, memory) and Acting (stitches, reflexes) must exist BEFORE Judging (Rating) is useful, because a score alone doesn't fix anything — FAZ supplies evidence to act correctly on findings (e.g., the ISFW policy example), and stitches give the fabric a way to respond to what Judging keeps finding.
